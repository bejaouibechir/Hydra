Lesson 7 of 11 · Pass parameters

Change one value without touching the YAML

Declare one typed output-file parameter, override it at run time, and prove that the same job writes to the requested scope.

hdrctl run -Pabout 10 minutesverbose run complete

1. Objective

Goal

Add parameters.yaml, replace the destination filename with Hydra's documented {{ param:output_file }} placeholder, and run the job with -P output_file=scoped-output.csv.

Why this matters

Copying a job for every date, tenant, or filename creates drift. Parameters keep the pipeline structure immutable while the caller supplies a value at execution time. The CLI override has the strongest job-level precedence, so the manifest stays reusable and reviewable.

Course project and evidence rule

Continue in cli-course. The job remains first-job, and workflow lessons add workflow.yaml beside it. The terminal excerpts shown here come from that cumulative project. Treat each verdict as evidence for this exact command, project state, and machine. Preserve the command beside the result when recording a run. Durations and process identifiers can vary without changing a successful state; do not turn them into thresholds. Verify instead the named files, resolved identifiers, row counters, step states, or HTTP status the command is designed to prove. Keep the manifest and generated data beside that record so another operator can reproduce the same check from a clean terminal. This small evidence bundle makes configuration drift visible and keeps the next lesson grounded in a known successful state. If one of those facts differs, reconcile the preceding lesson before continuing. Before moving on, keep a compact run record with the working directory, the command you typed, the manifests you changed, and the stable facts you confirmed. That record is more useful than a screenshot alone because another reader can reproduce it. Re-open the relevant generated file when the command writes data, and compare its header and content with the declared source, transformation order, destination, or dependency. This habit keeps the cumulative project honest: every new capability is added on top of a state that was observed, explained, and independently checkable rather than merely assumed, and easy to audit later.

Prerequisites

  • Lesson 6 completed and checked.
  • The validated first-job CSV project.
  • A terminal opened in the cli-course folder.

2. Steps

01Declare the parameter

Objective

Give output_file a type, default, and description.

Actions

  1. Create first-job/parameters.yaml.
  2. Add the parameters mapping exactly as shown.
  3. Keep the default equal to the file used in earlier lessons.
parameters:
  output_file:
    type: string
    default: output.csv
    description: Output CSV file name
What you should see

The declaration preserves the earlier behavior when no override is passed.

parameters:
  output_file:
    type: string
    default: output.csv
    description: Output CSV file name

02Use the parameter in the destination

Objective

Resolve the destination filename while retaining the job-relative data folder.

Actions

  1. Open first-job/destinations.yaml.
  2. Replace only load.table.
  3. Use the colon form of Hydra's parameter placeholder.
load:
  table: "data/{{ param:output_file }}"
  mode: replace
What you should see

The destination path combines a stable folder with a runtime-resolved filename.

table: "data/{{ param:output_file }}"

03Override the filename

Objective

Run the unchanged pipeline with a one-command output scope.

Actions

  1. Pass one KEY=VALUE pair with -P.
  2. Use a filename without path traversal so output remains under data.
hdrctl run first-job -P output_file=scoped-output.csv
What you should see

The actual run succeeds with the same observed row counts.

✅ Pipeline completed successfully in 3.2s
Rows read   : 3
Rows written: 2

04Read the parameterized output

Objective

Prove that the override selected a new destination file.

Actions

  1. Open first-job/data/scoped-output.csv.
  2. Compare the rows with the default output from lesson 5.
Get-Content first-job\data\scoped-output.csv
What you should see

The requested file exists and contains the two filtered rows.

id,name,value
1,Alice,100.0
2,Bob,200.0
