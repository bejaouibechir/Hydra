1. Objective

Goal

Run hdrctl list . from cli-course. Confirm that Hydra detects first-job, recognizes its required manifests, and labels its optional transformations without opening a connector.

Why this matters

Operators often need a quick inventory before choosing what to validate or run. list reads folder structure, so it is fast and side-effect free; its OK means required files are present, not that their contents or connections have passed the deeper gates.

Course project and evidence rule

Continue in cli-course. The job remains first-job, and workflow lessons add workflow.yaml beside it. The terminal excerpts shown here come from that cumulative project. Treat each verdict as evidence for this exact command, project state, and machine. Preserve the command beside the result when recording a run. Durations and process identifiers can vary without changing a successful state; do not turn them into thresholds. Verify instead the named files, resolved identifiers, row counters, step states, or HTTP status the command is designed to prove. Keep the manifest and generated data beside that record so another operator can reproduce the same check from a clean terminal. This small evidence bundle makes configuration drift visible and keeps the next lesson grounded in a known successful state. If one of those facts differs, reconcile the preceding lesson before continuing. Before moving on, keep a compact run record with the working directory, the command you typed, the manifests you changed, and the stable facts you confirmed. That record is more useful than a screenshot alone because another reader can reproduce it. Re-open the relevant generated file when the command writes data, and compare its header and content with the declared source, transformation order, destination, or dependency. This habit keeps the cumulative project honest: every new capability is added on top of a state that was observed, explained, and independently checkable rather than merely assumed.

Prerequisites

  • Lesson 7 completed and checked.
  • The validated first-job CSV project.
  • A terminal opened in the cli-course folder.

2. Steps

01Read the command contract

Objective

Confirm that list accepts only a search path and language option.

Actions

  1. Open the subcommand help.
  2. Verify there is no connection, strictness, or execution option.
hdrctl list --help
What you should see

The interface is intentionally small: an optional path plus global language and help.

Usage: hdrctl list [OPTIONS] [PATH]

Examples:
  hydra list
  hydra list jobs/

02Inventory the course folder

Objective

Detect the cumulative job from its manifest structure.

Actions

  1. Stay in cli-course.
  2. Run hdrctl list against the current folder.
hdrctl list .
What you should see

Hydra detects exactly the observed job and marks its required file set OK.

Jobs detected in C:\Users\DELL\Desktop\Hydra\conversation_files\cli-course

──────────────────────────────────────────────────────────────────────
first-job                      ✅ OK                        [transforms]
──────────────────────────────────────────────────────────────────────

1 job(s)  1 OK OK

03Interpret the optional marker

Objective

Read [transforms] as inventory metadata, not an execution result.

Actions

  1. Locate the bracketed marker beside first-job.
  2. Match it to first-job/transformations.yaml.
  3. Do not infer row counts or connector access from this line.
Get-ChildItem first-job -Filter *.yaml
What you should see

The job folder contains its core manifests plus transformations and parameters.

destinations.yaml
parameters.yaml
pipeline.yaml
sources.yaml
transformations.yaml

04Choose the next safe command

Objective

Move from inventory to the correct deeper check when needed.

Actions

  1. Use validate after manifest edits.
  2. Use test after connection changes.
  3. Use run only after both gates pass.
hdrctl validate first-job
hdrctl test first-job
What you should see

Inventory identifies the target; validation and testing provide the content and connector evidence.

✅ DSL valid — no errors detected.
✅ All tests pass — ready to execute.
