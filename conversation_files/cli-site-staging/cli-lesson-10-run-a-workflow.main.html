Run the workflow and follow every state

Execute the validated two-step DAG, follow each terminal state, and reconcile the final workflow result with the job output.

hdrctl workflow runabout 9 minutesworkflow validated

1. Objective

Goal

Run hdrctl workflow run workflow.yaml. Read the workflow start, the terminal status of run_first_job, the terminal status of record_completion, and the final 2/2 result.

Why this matters

A workflow is successful only when its required steps reach acceptable terminal states. Reading the per-step lines prevents a green summary from becoming a black box, while opening the job output connects orchestration state back to the data artifact.

Course project and evidence rule

Continue in cli-course. The job remains first-job, and workflow lessons add workflow.yaml beside it. The terminal excerpts shown here come from that cumulative project. Treat each verdict as evidence for this exact command, project state, and machine. Preserve the command beside the result when recording a run. Durations and process identifiers can vary without changing a successful state; do not turn them into thresholds. Verify instead the named files, resolved identifiers, row counters, step states, or HTTP status the command is designed to prove. Keep the manifest and generated data beside that record so another operator can reproduce the same check from a clean terminal. This small evidence bundle makes configuration drift visible and keeps the next lesson grounded in a known successful state. If one of those facts differs, reconcile the preceding lesson before continuing. Before moving on, keep a compact run record with the working directory, the command you typed, the manifests you changed, and the stable facts you confirmed. That record is more useful than a screenshot alone because another reader can reproduce it. Re-open the relevant generated file when the command writes data, and compare its header and content with the declared source, transformation order, destination, or dependency. This habit keeps the cumulative project honest: every new capability is added on top of a state that was observed, explained, and independently checkable rather than merely assumed.

2. Steps

01Revalidate immediately before execution

Objective

Use the validated manifest as the exact input to the run.

Actions

  1. Run the workflow validator once more after any edit.
  2. Proceed only when it returns the clean verdict.
hdrctl workflow validate workflow.yaml
What you should see

The same file that will run passes model and graph validation.

02Run the workflow

Objective

Execute the job step and its dependent completion action.

Actions

  1. Invoke hdrctl workflow run with the manifest path.
  2. Wait until both step lines and the final summary appear.
hdrctl workflow run workflow.yaml
What you should see

Both real steps reach OK and Hydra reports the observed total.
