Confirm Studio is talking to the engine

Confirm the visual editor is connected to Hydra's backend and know which evidence belongs to the API rather than the browser.

1. Objective

Goal

Read the top-bar status produced by the health query, verify /api/health, and identify the difference between API online, API offline, and the temporary ellipsis shown while the query is unresolved.

Why this matters

Studio is a React client; project lists, workflow files, runs, node metadata, and filesystem pickers come from the FastAPI backend. A working Vite page with an offline API can still render navigation while every data operation fails.

Course project

Keep one cumulative Studio project named studio-course, one manual workflow named guided-workflow, and one job named first-job. Each lesson builds on the state saved by the previous one.

Prerequisites

  • Hydra API started with hdrctl serve.
  • Studio started from Hydra/studio with npm run dev.
  • The preceding lesson completed before continuing.

02Verify health directly

Objective

Prove the application responds independently of the Studio component tree.

Actions

  1. Open a second terminal.
  2. Request the proxied health route while both processes are running.
  3. Read the HTTP response.
Invoke-WebRequest -UseBasicParsing http://localhost:5173/api/health
What you should see

Vite proxies the request to the backend and Hydra returns its running message.

StatusCode : 200
Content    : {"message":"Hydra ETL API is running"}

03Relate the two processes

Objective

Keep frontend and backend responsibilities distinct.

Actions

  1. Confirm Vite is serving Studio on port 5173.
  2. Confirm hdrctl serve is listening on port 5678.
  3. Leave both terminals running for the track.
hdrctl serve
cd studio
npm run dev
What you should see

The README-defined development arrangement is one API process plus one Vite process.

Hydra API running at http://127.0.0.1:5678
Local: http://localhost:5173/

Evidence rule

Record the visible label, selected scene, saved file, and stable state that each gesture proves. Counts tied to your workspace and run durations can change, so do not use them as fixed thresholds. When Studio writes YAML, compare the generated key with the field you edited; when it runs work, compare the node state with the Runs detail. This keeps the canvas, the DSL, and the engine tied to the same observable project instead of treating a green screen as sufficient evidence. Before continuing, reopen the saved node or panel and reproduce the observation from a neutral selection. Keep the project path, workflow name, job tab, active scene, and relevant field beside your note so another operator can repeat the same check. If a file is generated, inspect it on disk as well as in Studio. If a run is involved, wait for a terminal state and use the Runs page instead of relying on a transient animation. These habits reveal autosave, workspace, and scene mistakes early, while the project is still small enough to correct without obscuring the cause.
