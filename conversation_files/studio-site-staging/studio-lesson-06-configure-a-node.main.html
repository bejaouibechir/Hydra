Lesson 6 of 12 · Configure a node

Fill a node without writing YAML

Open the CSV node dialog, select a real fixture, save it, and understand exactly which source parameter Studio stores.

Inspectorabout 10 minutesCSV source placed

1. Objective

Goal

Double-click the CSV node, fill the required File path using Browse, and save. Use the repository fixture examples/minimal_csv/data/input.csv, which exists in the Hydra solution and was used by the CLI track.

Why this matters

The dialog is generated from CONFIG_FIELDS. For source_csv, the only required field is path; saving updates node data, and the serializer later turns that data into a CSV source declaration without requiring hand-written YAML.

Course project

Keep one cumulative Studio project named studio-course, one manual workflow named guided-workflow, and one job named first-job. Each lesson builds on the state saved by the previous one.

Prerequisites

  • Hydra API started with hdrctl serve.
  • Studio started from Hydra/studio with npm run dev.
  • The preceding lesson completed before continuing.

04Preserve secret boundaries

Objective

Apply the same inspector discipline to future database nodes.

Actions

  3. Never store a literal credential in the node.

Evidence rule

Record the visible label, selected scene, saved file, and stable state that each gesture proves. Counts tied to your workspace and run durations can change, so do not use them as fixed thresholds. When Studio writes YAML, compare the generated key with the field you edited; when it runs work, compare the node state with the Runs detail. This keeps the canvas, the DSL, and the engine tied to the same observable project instead of treating a green screen as sufficient evidence. Before continuing, reopen the saved node or panel and reproduce the observation from a neutral selection. Keep the project path, workflow name, job tab, active scene, and relevant field beside your note so another operator can repeat the same check. If a file is generated, inspect it on disk as well as in Studio. If a run is involved, wait for a terminal state and use the Runs page instead of relying on a transient animation. These habits reveal autosave, workspace, and scene mistakes early, while the project is still small enough to correct without obscuring the cause. They also leave a reproducible checkpoint for the next lesson and make later differences easier to attribute to one deliberate canvas change.
