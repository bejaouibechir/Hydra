Lesson 9 of 12 · Run the job

Launch from the canvas and follow each node

Start the completed job from its canvas, watch Studio poll the backend, and connect the final status to the configured nodes and output.

Run Jobabout 10 minutesjob ready

1. Objective

Goal

With first-job active, select Run Job. Follow the pending/running/success state that Studio applies to nodes, read the automatically opened LOGS panel, and verify the output file selected in lesson 8.

Why this matters

Studio starts an inline run by serializing the active canvas and sending it to the API with a working directory. It polls the run until terminal state, then derives log lines and node status from the backend result; the UI is a view of engine execution, not a separate simulator.

Course project

Continue with studio-course, the manual guided-workflow, and the first-job canvas saved by the preceding lesson. Do not create a parallel replacement project.

Prerequisites

  • The top bar shows API online.
  • The cumulative workflow is open in the editor.
  • The preceding lesson checklist is complete.

Evidence rule

Record the active scene, visible label, saved file, and stable state that each gesture proves. Workspace counts and run durations can change, so do not turn them into fixed thresholds. When Studio writes YAML, compare the generated key with the field you edited; when it runs work, compare the node state with the Runs detail. This evidence bundle keeps the canvas, the DSL, and the engine tied to the same observable project instead of treating a green badge or animation as sufficient proof. Before continuing, reopen the saved node or panel and reproduce the observation from a neutral selection. Keep the project path, workflow name, job tab, active scene, and relevant field beside your note so another operator can repeat the same check. If a file is generated, inspect it on disk as well as in Studio. If a run is involved, wait for a terminal state and use the Runs page instead of relying on a transient animation. These habits reveal autosave, workspace, and scene mistakes early, while the project is still small enough to correct without obscuring the cause.
