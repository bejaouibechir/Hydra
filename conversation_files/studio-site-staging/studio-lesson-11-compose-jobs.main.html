Lesson 11 of 12 · Compose jobs

Turn your jobs into an ordered workflow

Move from one executable job to orchestration by placing saved jobs on the workflow canvas and drawing one explicit dependency.

Workflow configurationabout 12 minutesrun reviewed

1. Objective

Goal

Create a second job tab named second-job, then switch to Workflow configuration. Drag first-job and second-job from the dynamic Jobs section and connect the first to the second.

Why this matters

Workflow job nodes are references to independently saved job canvases. The serializer injects readable job paths and turns incoming edges into depends_on; the tested DAG utilities reject cycles and unknown dependencies before saving or running.

Course project

Continue with studio-course, the manual guided-workflow, and the first-job canvas saved by the preceding lesson. Do not create a parallel replacement project.

Prerequisites

  • The top bar shows API online.
  • The cumulative workflow is open in the editor.
  • The preceding lesson checklist is complete.

Objective

04Read generated dependency YAML

Objective

Verify the visual edge becomes depends_on rather than job-internal pipeline flow.

Actions

  1. Select Hydra DSL in workflow scene.
  2. Find the second workflow step.
  3. Read its job and depends_on values.
Workflow configuration → Hydra DSL
What you should see

The serializer emits job steps and derives the second dependency from the edge.

- name: second-job
  type: job
  job: ../jobs/second-job
  depends_on:
    - first-job
Evidence rule

Record the active scene, visible label, saved file, and stable state that each gesture proves. Workspace counts and run durations can change, so do not turn them into fixed thresholds. When Studio writes YAML, compare the generated key with the field you edited; when it runs work, compare the node state with the Runs detail. This evidence bundle keeps the canvas, the DSL, and the engine tied to the same observable project instead of treating a green badge or animation as sufficient proof. Before continuing, reopen the saved node or panel and reproduce the observation from a neutral selection. Keep the project path, workflow name, job tab, active scene, and relevant field beside your note so another operator can repeat the same check. If a file is generated, inspect it on disk as well as in Studio. If a run is involved, wait for a terminal state and use the Runs page instead of relying on a transient animation. These habits reveal autosave, workspace, and scene mistakes early, while the project is still small enough to correct without obscuring the cause. They also leave a reproducible checkpoint for the next lesson and make later differences easier to attribute to one deliberate canvas change.
