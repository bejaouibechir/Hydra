## 📊 JUSTIFICATION DU CHANGEMENT

### **Problème Identifié**

L'architecture actuelle d'Hydra est **excellente pour SQL** (CSV, MySQL, PostgreSQL) mais présente des limitations pour les systèmes **non-tabulaires** :

```
SYSTÈMES RÉGULIERS (Table-Like)     SYSTÈMES IRRÉGULIERS (Non-Table-Like)
├── CSV                             ├── MongoDB (documents JSON imbriqués)
├── MySQL                           ├── Kafka (stream événements infinis)
├── PostgreSQL                      ├── Prometheus (métriques time-series)
├── Oracle                          ├── Elasticsearch (documents indexés)
└── SQL Server                      └── AWS S3 (objets non structurés)

Interface actuelle:                 Problèmes:
✅ table: str                       ❌ "table" pour topic Kafka ?
✅ query: str (SQL)                 ❌ Query pour filter MongoDB ?
✅ batch_size: int                  ❌ Batch pour stream infini ?
```

### **Impact si Non Résolu**

| Scénario            | Sans Fondations            | Avec Fondations         |
| ------------------- | -------------------------- | ----------------------- |
| **Ajouter MongoDB** | 12-16h + refactoring core  | 6-8h (adapter isolé)    |
| **Ajouter Kafka**   | 16-20h + refactoring core  | 8-10h (adapter isolé)   |
| **Maintenance**     | Logique complexe dans core | Core simple + adapters  |
| **Tests**           | Tests couplés difficiles   | Tests unitaires faciles |

**Dette Technique Évitée** : ~40h sur 3 prochains connecteurs

## 🏗️ ARCHITECTURE CIBLE

### **Pattern ADAPTER pour Systèmes Irréguliers**

```
┌─────────────────────────────────────────────────────┐
│              HYDRA CORE (stable)                    │
│  - Executor (table-like universel)                  │
│  - Interface Connector (inchangée)                  │
│  - Parsers Pydantic (validation stricte)            │
└────────────────────┬────────────────────────────────┘
                     │
     ┌───────────────┴───────────────┐
     │                               │
┌────▼─────────────┐      ┌─────────▼──────────────┐
│ CONNECTEURS SQL  │      │ CONNECTEURS NON-SQL    │
│ (directs)        │      │ (via adapters)         │
├──────────────────┤      ├────────────────────────┤
│ • MySQL          │      │ • Kafka ───┐           │
│ • PostgreSQL     │      │ • MongoDB ─┤           │
│ • Oracle         │      │ • Prometheus│          │
└──────────────────┘      └─────────────┼──────────┘
                                        │
                          ┌─────────────▼────────────┐
                          │   ADAPTER LAYER          │
                          │  (nouveau module)        │
                          ├──────────────────────────┤
                          │ • KafkaToTableAdapter    │
                          │ • MongoToTableAdapter    │
                          │ • PrometheusToTableAdapter│
                          └──────────────────────────┘

Principe: "Adapters normalisent l'irrégulier → table-like"
```

### **Exemple Concret : MongoDB**

**Sans Adapter (complexe)** :

```python
# Logique imbrication/aplatissement dans MySQLConnector
# → Couplage fort, difficile à tester, non réutilisable
class MongoDBConnector(Connector):
    def extract_batches(self, table, ...):
        # Logique complexe flatten documents
        # Gestion arrays, nested dicts, etc.
        # 200+ lignes de code
```

**Avec Adapter (simple)** :

```python
# Adapter isolé, testable, réutilisable
class MongoToTableAdapter:
    def to_batches(self) -> Iterator[Batch]:
        for doc in self.collection.find():
            row = self._flatten(doc)  # Isolation complexité
            yield row

# Connecteur minimaliste
class MongoDBConnector(Connector):
    def extract_batches(self, table, ...):
        adapter = MongoToTableAdapter(...)
        yield from adapter.to_batches()  # 5 lignes
```

```python
"""
Module adapters pour systèmes non-tabulaires.

Principe:
- Chaque adapter transforme données irrégulières → table-like
- Interface commune TableAdapter
- Isolation complexité hors du core
"""

from abc import ABC, abstractmethod
from typing import Iterator, Dict, Any, List

# Types réutilisés depuis connector.interface
Row = Dict[str, Any]
Batch = List[Row]


class TableAdapter(ABC):
    """
    Interface commune pour tous les adapters.

    Responsabilité:
    - Transformer données source non-tabulaire → batches table-like
    - Isolation logique flatten/normalize/serialize
    - Testable indépendamment du core
    """

    @abstractmethod
    def to_batches(self, batch_size: int) -> Iterator[Batch]:
        """
        Convertit source irrégulière en batches de Row.

        Returns:
            Iterator[Batch]: Batches compatibles Hydra Core
        """
        raise NotImplementedError

    @abstractmethod
    def validate_config(self) -> None:
        """
        Valide configuration adapter-spécifique.

        Raises:
            ValueError: Si config invalide
        """
        raise NotImplementedError
```

- ✅ Interface `TableAdapter` définie

#### **Tâche 1.2 : Exemple Adapter Template**

**Fichier** : `internal/adapters/base_flatten_adapter.py`

```python
"""
Adapter de base pour flattening documents imbriqués.

Utilisable par MongoDB, Elasticsearch, JSON APIs, etc.
"""

import json
from typing import Dict, Any, List
from internal.adapters import TableAdapter, Batch


class BaseFlattenAdapter(TableAdapter):
    """
    Adapter générique pour aplatir documents imbriqués.

    Stratégies:
    1. Nested dicts → colonnes préfixées (address.city)
    2. Arrays → sérialisation JSON string
    3. Objets complexes → JSON string
    """

    def _flatten_document(
        self,
        doc: Dict[str, Any],
        prefix: str = "",
        separator: str = "_"
    ) -> Dict[str, Any]:
        """
        Aplatit récursivement un document imbriqué.

        Exemple:
            Input:  {"user": {"name": "John", "age": 30}}
            Output: {"user_name": "John", "user_age": 30}

        Args:
            doc: Document source (dict potentiellement imbriqué)
            prefix: Préfixe pour colonnes (pour récursion)
            separator: Séparateur niveaux imbrication

        Returns:
            Dict[str, Any]: Document aplati (1 niveau)
        """
        flat = {}

        for key, value in doc.items():
            full_key = f"{prefix}{separator}{key}" if prefix else key

            if isinstance(value, dict):
                # Récursion pour dicts imbriqués
                nested_flat = self._flatten_document(
                    value,
                    prefix=full_key,
                    separator=separator
                )
                flat.update(nested_flat)

            elif isinstance(value, list):
                # Arrays → JSON string (évite explosion lignes)
                flat[full_key] = json.dumps(value)

            else:
                # Valeurs scalaires → conservation directe
                flat[full_key] = value

        return flat

    def validate_config(self) -> None:
        """Validation de base (override si besoin spécifique)."""
        pass
```

**Livrables** :

- ✅ Logique flatten réutilisable
- ✅ Gestion nested dicts
- ✅ Sérialisation arrays (évite 1-to-many rows)

```python
from abc import abstractmethod
from typing import List

class BaseDBConnector(Connector):
    """Base class pour tous les connecteurs SQL."""

    # ======== NOUVEAU : Support Upsert ========

    @abstractmethod
    def _build_upsert_sql(
        self,
        table: str,
        columns: List[str],
        key_columns: List[str]
    ) -> str:
        """
        Construit requête SQL UPSERT selon dialecte DB.

        Chaque DB a sa propre syntaxe:
        - MySQL/MariaDB: INSERT ... ON DUPLICATE KEY UPDATE
        - PostgreSQL: INSERT ... ON CONFLICT DO UPDATE
        - Oracle: MERGE INTO ... USING DUAL
        - SQL Server: MERGE INTO ... USING

        Args:
            table: Nom table cible (quoté via _q())
            columns: Toutes colonnes du DataFrame
            key_columns: Colonnes constituant clé de conflit

        Returns:
            str: Requête SQL paramétrée (placeholders %s, $1, etc.)

        Raises:
            NotImplementedError: Si DB ne supporte pas upsert
            ValueError: Si config invalide (ex: key_columns vide)

        Exemples:
            MySQL:
                INSERT INTO users (id, name, email)
                VALUES (%s, %s, %s)
                ON DUPLICATE KEY UPDATE name=VALUES(name), email=VALUES(email)

            PostgreSQL:
                INSERT INTO users (id, name, email)
                VALUES ($1, $2, $3)
                ON CONFLICT (id) DO UPDATE SET name=EXCLUDED.name
        """
        raise NotImplementedError(
            f"{self.__class__.__name__} does not implement upsert. "
            f"Override _build_upsert_sql() to add support, or set "
            f"capabilities.supports_upsert=False to disable."
        )

    def _validate_upsert_params(
        self,
        table: str,
        columns: List[str],
        key_columns: List[str]
    ) -> None:
        """
        Validation commune paramètres upsert (mutualisée).

        Checks:
        1. table non vide
        2. columns non vide
        3. key_columns non vide
        4. key_columns ⊆ columns
        5. Au moins 1 colonne non-clé (pour UPDATE)

        Raises:
            ValueError: Si validation échoue avec message contexte
        """
        if not table or not table.strip():
            raise ValueError(
                f"{self.__class__.__name__} [{self.name}]: "
                f"table name cannot be empty"
            )

        if not columns:
            raise ValueError(
                f"{self.__class__.__name__} [{self.name}]: "
                f"columns list cannot be empty"
            )

        if not key_columns:
            raise ValueError(
                f"{self.__class__.__name__} [{self.name}]: "
                f"key_columns list cannot be empty for upsert mode"
            )

        # Vérifier clés existent dans columns
        missing_keys = set(key_columns) - set(columns)
        if missing_keys:
            raise ValueError(
                f"{self.__class__.__name__} [{self.name}]: "
                f"key columns {sorted(missing_keys)} not found in DataFrame. "
                f"Available columns: {sorted(columns)}"
            )

        # Vérifier au moins 1 colonne non-clé (sinon UPDATE vide)
        key_set = set(key_columns)
        update_columns = [c for c in columns if c not in key_set]

        if not update_columns:
            raise ValueError(
                f"{self.__class__.__name__} [{self.name}]: "
                f"upsert requires at least one non-key column to update. "
                f"All columns {columns} are part of key {key_columns}"
            )

    @property
    def capabilities(self) -> ConnectorCapabilities:
        """
        Déclare capacités du connecteur.

        Override dans classe fille pour activer upsert:
            @property
            def capabilities(self):
                return ConnectorCapabilities(
                    supports_transactions=True,
                    supports_upsert=True  # ← MySQL/PostgreSQL
                )
        """
        return ConnectorCapabilities()
```

**Livrables** :

- ✅ Méthode abstraite `_build_upsert_sql()`
- ✅ Validation mutualisée `_validate_upsert_params()`
- ✅ Documentation exhaustive avec exemples multi-DB
- ✅ Pattern extension clair pour futures DB

```python
from typing import Protocol, Callable

class ConnectorFactory(Protocol):
    """Protocol pour factories de connecteurs."""
    def __call__(self, name: str, config: Dict[str, Any]) -> Connector:
        ...


def _build_csv_connector(name: str, config: Dict[str, Any]) -> Connector:
    """Factory CSV avec injection job_dir."""
    job_dir = config.get("job_dir")
    if not job_dir:
        raise ValueError(
            f"CSV Connector '{name}' requires 'job_dir' in config. "
            f"Executor must inject it via config['job_dir']."
        )
    return CSVConnector(name, config, job_dir)


def _build_db_connector(connector_class: Type[BaseDBConnector]):
    """Factory générique pour connecteurs DB (signature standard)."""
    def factory(name: str, config: Dict[str, Any]) -> Connector:
        return connector_class(name, config)
    return factory


# Registry avec factories (extensible sans if/elif)
CONNECTOR_REGISTRY: Dict[str, ConnectorFactory] = {
    "csv": _build_csv_connector,
    "mysql": _build_db_connector(MySQLMariaDBConnector),
    "mariadb": _build_db_connector(MySQLMariaDBConnector),
    # Ajout futur trivial:
    # "mongodb": _build_mongo_connector,
    # "kafka": _build_kafka_connector,
}


def build_connector(*, name: str, config: Dict[str, Any]) -> Connector:
    """
    Factory de connecteurs avec validation type.

    Raises:
        ValueError: Si type inconnu ou factory échoue
    """
    ctype = config.get("type", "").strip().lower()

    if not ctype:
        raise ValueError(f"Connector '{name}': 'type' is required")

    factory = CONNECTOR_REGISTRY.get(ctype)

    if factory is None:
        available = ", ".join(sorted(CONNECTOR_REGISTRY.keys()))
        raise ValueError(
            f"Connector '{name}': unknown type '{ctype}'. "
            f"Available types: {available}"
        )

    # Délégation à la factory (chaque factory sait ce dont elle a besoin)
    return factory(name, config)
```

**Livrables** :

- ✅ Élimination dispatch hardcodé
- ✅ Chaque factory encapsule sa logique
- ✅ Ajout MongoDB/Kafka trivial (1 ligne registry)

### **Tâche 2.1 : Extension LoadConfig**

**Fichier** : `internal/parser/destination.py`

```python
from enum import Enum
from typing import Optional, List
from pydantic import BaseModel, Field, field_validator, model_validator


class LoadMode(str, Enum):
    """Modes de chargement supportés."""
    APPEND = "append"
    REPLACE = "replace"
    UPSERT = "upsert"


class LoadConfig(BaseModel):
    """
    Configuration section load (destination).

    Validation stricte:
    - mode upsert → key obligatoire
    - key peut être clé simple ou composite
    """

    table: str = Field(..., min_length=1)
    mode: LoadMode = LoadMode.APPEND
    key: Optional[List[str]] = Field(default=None, min_length=1)
    batch_size: int = Field(default=1000, ge=100, le=10_000)

    @field_validator('key')
    @classmethod
    def clean_key_columns(cls, v: Optional[List[str]]) -> Optional[List[str]]:
        """
        Nettoie et valide colonnes de clé.

        - Trim whitespace
        - Rejette strings vides
        - Déduplique (conserve ordre)
        """
        if v is None:
            return None

        cleaned = []
        seen = set()

        for col in v:
            if not isinstance(col, str):
                raise ValueError(f"key column must be string, got {type(col)}")

            col_clean = col.strip()

            if not col_clean:
                raise ValueError("key columns cannot be empty strings")

            # Déduplication
            if col_clean not in seen:
                cleaned.append(col_clean)
                seen.add(col_clean)

        if not cleaned:
            raise ValueError("key list cannot be empty after cleaning")

        return cleaned

    @model_validator(mode='after')
    def validate_upsert_requires_key(self):
        """
        Validation cross-champs : mode upsert nécessite key.

        Exemples valides:
            mode: upsert, key: [id]
            mode: upsert, key: [region, product_id]

        Exemples invalides:
            mode: upsert, key: null  ← ValueError
            mode: upsert, key: []    ← ValueError
        """
        if self.mode == LoadMode.UPSERT and not self.key:
            raise ValueError(
                "mode 'upsert' requires 'key' parameter. "
                "Specify primary key or unique key columns. "
                "Examples:\n"
                "  key: [id]                    # Simple key\n"
                "  key: [region, product_id]    # Composite key"
            )

        return self
```

**Livrables** :

- ✅ Enum `LoadMode` (évite typos)
- ✅ Champ `key: Optional[List[str]]`
- ✅ Validation cross-champs Pydantic
- ✅ Messages d'erreur avec exemples

### **Tâche 2.2 : Implémentation MySQL _build_upsert_sql()**

**Fichier** : `internal/connector/mysql_mariadb_connector.py`

```python
from typing import List

class MySQLMariaDBConnector(BaseDBConnector):
    """Connecteur MySQL/MariaDB avec support upsert."""

    def _build_upsert_sql(
        self,
        table: str,
        columns: List[str],
        key_columns: List[str]
    ) -> str:
        """
        Génère INSERT ... ON DUPLICATE KEY UPDATE pour MySQL/MariaDB.

        Logique:
        1. Valider params (via _validate_upsert_params)
        2. Calculer update_columns = columns - key_columns
        3. Construire INSERT standard
        4. Ajouter ON DUPLICATE KEY UPDATE
        5. Exclure key_columns du UPDATE (MySQL n'aime pas UPDATE sur PK)

        Exemple:
            Table: users (id PK, name, email, age)
            key_columns: [id]

            SQL généré:
            INSERT INTO `users` (`id`, `name`, `email`, `age`)
            VALUES (%s, %s, %s, %s)
            ON DUPLICATE KEY UPDATE
                `name`=VALUES(`name`),
                `email`=VALUES(`email`),
                `age`=VALUES(`age`)

        Clé composite:
            Table: sales (region, product_id PK, quantity, revenue)
            key_columns: [region, product_id]

            SQL généré:
            INSERT INTO `sales` (`region`, `product_id`, `quantity`, `revenue`)
            VALUES (%s, %s, %s, %s)
            ON DUPLICATE KEY UPDATE
                `quantity`=VALUES(`quantity`),
                `revenue`=VALUES(`revenue`)
        """
        # 1. Validation commune (mutualise checks)
        self._validate_upsert_params(table, columns, key_columns)

        # 2. Calculer colonnes à mettre à jour (tout sauf clés)
        key_set = set(key_columns)
        update_columns = [c for c in columns if c not in key_set]

        # 3. Quoting identifiants SQL
        quoted_table = self._q(table)
        quoted_columns = [self._q(c) for c in columns]
        quoted_update_columns = [self._q(c) for c in update_columns]

        # 4. Construction INSERT
        cols_str = ", ".join(quoted_columns)
        placeholders = ", ".join(["%s"] * len(columns))

        # 5. Construction ON DUPLICATE KEY UPDATE
        # Syntaxe MySQL: col=VALUES(col)
        update_parts = [
            f"{col}=VALUES({col})" for col in quoted_update_columns
        ]
        update_str = ", ".join(update_parts)

        # 6. Assemblage final
        sql = (
            f"INSERT INTO {quoted_table} ({cols_str}) "
            f"VALUES ({placeholders}) "
            f"ON DUPLICATE KEY UPDATE {update_str}"
        )

        return sql

    @property
    def capabilities(self):
        """MySQL/MariaDB supportent transactions et upsert."""
        return ConnectorCapabilities(
            supports_transactions=True,
            supports_upsert=True,
            supports_incremental=False,  # Pas encore implémenté
            is_tabular=True,
            supports_custom_queries=True,
        )
```

**Livrables** :

- ✅ Génération SQL MySQL correcte
- ✅ Exclusion automatique key_columns du UPDATE
- ✅ Support clés composites

### **Tâche 2.3 : Modification load_batches() pour Upsert**

**Fichier** : `internal/connector/mysql_mariadb_connector.py`

```python
from typing import Iterable, Optional, List

def load_batches(
    self,
    batches: Iterable[Batch],
    *,
    table: str,
    mode: str = "append",
    key: Optional[List[str]] = None,
) -> None:
    """
    Charge batches vers MySQL/MariaDB.

    Modes supportés:
    - append: INSERT simple (erreur si clé existe)
    - replace: TRUNCATE puis INSERT
    - upsert: INSERT ON DUPLICATE KEY UPDATE (NOUVEAU)

    Args:
        batches: Itérable de Batch (streaming)
        table: Nom table cible
        mode: Mode chargement (append|replace|upsert)
        key: Colonnes clé (obligatoire si mode=upsert)

    Raises:
        ValueError: Si mode invalide ou config incorrecte
    """
    # Validation table
    if not isinstance(table, str) or not table.strip():
        raise ValueError(
            f"{self.__class__.__name__} [{self.name}]: "
            f"table must be non-empty string"
        )
    table = table.strip()

    # Validation mode
    valid_modes = ("append", "replace", "upsert")
    if mode not in valid_modes:
        raise ValueError(
            f"{self.__class__.__name__} [{self.name}]: "
            f"mode '{mode}' not supported. "
            f"Supported modes: {', '.join(valid_modes)}"
        )

    # Validation upsert
    if mode == "upsert" and not key:
        raise ValueError(
            f"{self.__class__.__name__} [{self.name}]: "
            f"mode 'upsert' requires 'key' parameter. "
            f"Specify primary key or unique key columns."
        )

    # Connexion
    conn = self._connect()

    try:
        cur = conn.cursor()

        # Mode replace : TRUNCATE avant insertion
        if mode == "replace":
            cur.execute(f"TRUNCATE TABLE {self._q(table)}")
            conn.commit()

        # Traitement batch par batch
        first_columns: Optional[List[str]] = None
        sql_statement: Optional[str] = None

        for batch in batches:
            # Skip empty batches
            if not batch:
                continue

            # Inférer colonnes du premier batch (schéma stable)
            if first_columns is None:
                first_columns = self._infer_columns_from_batch(batch)

            # Construire SQL selon le mode (une seule fois)
            if sql_statement is None:
                if mode == "upsert":
                    # ✅ NOUVEAU : Utilise _build_upsert_sql()
                    sql_statement = self._build_upsert_sql(
                        table=table,
                        columns=first_columns,
                        key_columns=key
                    )
                else:
                    # Mode append : INSERT classique
                    sql_statement, _ = self._build_insert_many_sql(
                        table=table,
                        columns=first_columns,
                        batch=batch  # Pour structure
                    )

            # Extraire valeurs du batch (ordre colonnes important)
            values = [
                [row.get(col) for col in first_columns]
                for row in batch
            ]

            # Exécution batch
            cur.executemany(sql_statement, values)
            conn.commit()

        cur.close()

    except Exception as e:
        # Rollback best-effort
        try:
            conn.rollback()
        except Exception:
            pass

        raise ValueError(
            f"{self.__class__.__name__} [{self.name}]: "
            f"load failed.\n"
            f"  Table: {table}\n"
            f"  Mode : {mode}\n"
            f"  Key  : {key}\n"
            f"  Error: {type(e).__name__}: {e}"
        ) from e

    finally:
        # Fermeture connexion
        try:
            conn.close()
        except Exception:
            pass
```

```python
def _validate_destination_capabilities(
    self,
    dest_connector: Connector,
    load_config: Any  # LoadConfig Pydantic
) -> None:
    """
    Valide que destination supporte mode demandé.

    Checks:
    1. Mode upsert → connecteur doit supporter upsert
    2. Mode upsert → key obligatoire (double validation parser)

    Raises:
        ValueError: Si capabilities insuffisantes
    """
    mode = getattr(load_config, "mode", None)
    key = getattr(load_config, "key", None)

    # Validation upsert
    if mode == "upsert":
        # Check capability
        if not dest_connector.capabilities.supports_upsert:
            ctype = dest_connector.config.get("type", "unknown")
            raise ValueError(
                f"Destination '{dest_connector.name}' (type={ctype}) "
                f"does not support mode 'upsert'. "
                f"Supported modes: append, replace."
            )

        # Double validation key (après parser)
        if not key:
            raise ValueError(
                f"Destination '{dest_connector.name}': "
                f"mode 'upsert' requires 'key' parameter."
            )
```
