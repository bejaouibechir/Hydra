## 🔑 FONCTIONNALITÉS TECHNIQUES

### 1. Génération SQL Upsert

```sql
INSERT INTO users (id, name, email)
VALUES (1, 'Alice', 'alice@example.com')
ON DUPLICATE KEY UPDATE
  name = VALUES(name),
  email = VALUES(email)
```

**Support** :

- ✅ Clés simples : `key: [id]`
- ✅ Clés composites : `key: [region, product_id]`
- ✅ Protection injection SQL
- ✅ Syntaxe MySQL/MariaDB optimisée

### 2. Validation Pydantic

```yaml
load:
  table: employees
  mode: upsert        # Enum strict
  key: [id]           # Obligatoire si upsert
  batch_size: 1000
```

**Validations** :

- ✅ Mode upsert → key obligatoire
- ✅ Nettoyage whitespace colonnes
- ✅ Déduplication automatique
- ✅ Messages d'erreur clairs

### 3. Tests E2E Robustes

- ✅ Utilise containers Docker existants (hydra_mysql_test)
- ✅ Tables isolées (préfixe `e2e_`)
- ✅ Auto-cleanup entre tests
- ✅ Fixtures pytest réutilisables

## 🎓 DÉFIS & SOLUTIONS

### Défi 1 : Mock Capabilities

**Problème** : Mock `ConnectorCapabilities` complexe  
**Solution** : Validation par type connecteur au lieu d'objet capabilities

### Défi 2 : Patch Imports

**Problème** : `patch('registry.build_connector')` ne marche pas  
**Solution** : `patch.object(JobExecutor, '_build_connector')`

### Défi 3 : Configuration Tests E2E

**Problème** : Credentials MySQL incorrects  
**Solution** : Adaptation à l'infrastructure Docker existante (user `hydra`, DB `hydra_test`)

### Défi 4 : Verbosité Excessive

**Problème** : Réponses trop longues → tokens gaspillés  
**Solution** : Réduction 70% verbosité, focus fichiers livrables
