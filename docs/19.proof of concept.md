## 🔬 À QUOI SERT CE POC ?

Le POC (Proof of Concept) est **critique** avant de commencer le Sprint 4. Voici pourquoi :

---

## 🎯 OBJECTIF PRINCIPAL

**Valider que l'approche technique fonctionne AVANT d'investir 20h de développement.**

**Analogie** : C'est comme tester la solidité d'un pont avec un petit véhicule avant de faire passer des camions.

---

## ❓ LES 3 QUESTIONS CRITIQUES

### **Question 1 : Pandas peut-il gérer nos cas JSON ?**

**Sans POC** : On suppose que oui → 10h de code → Découverte : ça ne marche pas → Refonte totale

**Avec POC** : 2h de tests → Validation : ça marche ✅ → 18h de développement serein

---

### **Question 2 : La performance est-elle acceptable ?**

**Test POC** :
```python
# Générer 10 000 records nested
data = [{"id": i, "user": {"name": f"User{i}"}} for i in range(10000)]

# Flatten
start = time.time()
df = json_normalize(data, max_level=2)
elapsed = time.time() - start

# Critère : < 1 seconde
assert elapsed < 1.0
```

**Si ça prend 5 secondes** → Pandas n'est pas adapté → Chercher alternative (polars, pyarrow)

**Si ça prend 0.3 secondes** → ✅ GO Sprint 4

---

### **Question 3 : Les edge cases sont-ils gérés ?**

**Tests POC** :
```python
# Types mixtes
data = [
    {"id": 1, "value": 100},      # int
    {"id": 2, "value": "text"},   # string
    {"id": 3, "value": None}      # null
]

# Pandas gère-t-il sans crash ?
df = pd.DataFrame(data)  # dtype=object
```

**Si crash** → Problème → Revoir approche

**Si OK** → ✅ Confiance dans pandas

## 📊 CE QUE LE POC VALIDE CONCRÈTEMENT

### **Test 1 : JSON flat**
```python
data = [{"id": 1, "name": "Alice"}]
df = pd.DataFrame(data)
```
**Valide** : Pandas gère JSON simple ✅

---

### **Test 2 : JSON nested 1 niveau**
```python
data = [{"id": 1, "user": {"name": "Alice"}}]
df = json_normalize(data, max_level=1)
# Résultat : id | user.name
```
**Valide** : Flatten 1 niveau fonctionne ✅

---

### **Test 3 : JSON nested 2 niveaux + arrays**
```python
data = [{
    "id": 1,
    "user": {
        "name": "Alice",
        "addresses": [
            {"city": "Paris"},
            {"city": "Lyon"}
        ]
    }
}]

df = json_normalize(data, record_path=["user", "addresses"], meta=["id"])
# Résultat : 2 lignes (1 par adresse)
```
**Valide** : Arrays explode fonctionne ✅

---

### **Test 4 : Types mixtes**
```python
data = [
    {"value": 100},
    {"value": "text"},
    {"value": None}
]
df = pd.DataFrame(data)
```
**Valide** : Pandas gère sans crash (dtype=object) ✅

---

### **Test 5 : JSONL streaming**
```python
lines = ['{"id": 1}', '{"id": 2}', '{"id": 3}']
records = [json.loads(line) for line in lines]
df = pd.DataFrame(records)
```
**Valide** : Streaming ligne par ligne fonctionne ✅

---

### **Test 6 : Performance**
```python
# 10 000 records nested
data = [{"id": i, "user": {"name": f"User{i}"}} for i in range(10000)]

start = time.time()
df = json_normalize(data)
elapsed = time.time() - start

print(f"Temps : {elapsed:.3f}s")
print(f"Rows/sec : {len(df)/elapsed:.0f}")
```
**Critère** : <1s pour 10k records

**Si OK** : ✅ Performance acceptable

**Si KO** : ❌ Chercher alternative

---

### **Test 7 : Gestion erreurs**
```python
# JSON invalide
try:
    json.loads('{"invalid": ')
except json.JSONDecodeError as e:
    print(f"Ligne {e.lineno}, col {e.colno}: {e.msg}")
```
**Valide** : Erreurs actionnables disponibles ✅

---

## 🚦 CRITÈRE GO / NO-GO

### **SI 7/7 tests passent** → ✅ **GO Sprint 4**
- Pandas est adapté
- Performance OK
- Edge cases gérés
- → Développement serein

### **SI <6/7 tests passent** → ❌ **NO-GO**
- Pandas inadapté
