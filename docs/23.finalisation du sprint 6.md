## 🚀 FONCTIONNALITÉS IMPLÉMENTÉES

### Extract (Lecture)

```yaml
sources:
  my_parquet:
    type: parquet
    extract:
      file: "data/input.parquet"
      batch_size: 10000  # Configurable
```

**Capacités:**

- ✅ Lecture par batch (streaming)
- ✅ Batch size configurable
- ✅ Support fichiers vides
- ✅ Support tous types Parquet
- ✅ Gestion erreurs robuste

### Load (Écriture)

```yaml
destinations:
  output_parquet:
    type: parquet
    load:
      table: "output/results.parquet"
      mode: replace              # append | replace
      compression: snappy        # snappy | gzip | brotli | none
```

**Capacités:**

- ✅ Mode replace (remplacement complet)
- ✅ Mode append (ajout incrémental avec validation schéma)
- ✅ 4 compressions supportées
- ✅ Création automatique répertoires parents
- ✅ Validation compatibilité schéma

### Compressions Supportées

| Compression         | Ratio      | Vitesse      | Cas d'usage                    |
| ------------------- | ---------- | ------------ | ------------------------------ |
| **snappy** (défaut) | Bon        | Très rapide  | Pipelines quotidiens           |
| **gzip**            | Excellent  | Moyen        | Archivage, transfert           |
| **brotli**          | Excellent+ | Lent         | Stockage long terme            |
| **none**            | Aucun      | Ultra rapide | Debug, données pré-compressées |

### Exemples d'Utilisation

#### Exemple 1: Pipeline Simple

```yaml
# sources.yaml
sources:
  orders_source:
    type: parquet
    extract:
      file: "data/orders.parquet"

# destinations.yaml
destinations:
  orders_dest:
    type: parquet
    load:
      table: "output/processed_orders.parquet"
      mode: replace
      compression: gzip

# pipeline.yaml
pipeline:
  from: orders_source
  to: orders_dest
```

#### Exemple 2: Avec Transformations

```yaml
# transformations.yaml
transformations:
  calculate_totals:
    steps:
      - calculate:
          column: "total"
          expr: "quantity * price"

# pipeline.yaml
pipeline:
  from: orders_source
  transform: calculate_totals
  to: orders_dest
```

## 🚧 LIMITATIONS CONNUES

### Limitations Actuelles

1. **Pas d'upsert** - Mode upsert non supporté (limitation format fichier)
   
   - Contournement: Utiliser une base de données pour upsert

2. **Pas d'incremental** - Lecture complète uniquement (pas de CDC)
   
   - Contournement: Partitionnement manuel par date/période

3. **Schéma strict en append** - Incompatibilité schéma = erreur
   
   - Comportement: Par design pour intégrité des données

### Non-Objectifs Sprint 6

- ❌ Partitionnement Hive (Sprint futur)
- ❌ Predicate pushdown (Sprint futur)
