Voici une **version ultra-compacte (3 blocs)**, idéale pour une slide ou une discussion exécutive :

```
┌──────────────────────────────────────────────┐
│                CONTROL PLANE                 │
│                                              │
│  CLI / API                                   │
│  etl/engine.py                               │
│  Config + Secrets (resolvers, plugins)       │
│  Parsers YAML → Plan d’exécution (AST)       │
│  Hooks • Error handlers • Logs • Metrics     │
└───────────────────────────┬──────────────────┘
                            │
                            ▼
┌──────────────────────────────────────────────┐
│                EXECUTION CORE                │
│                                              │
│  Runner / Executor                            │
│  Context (job, stats, params runtime)        │
│  Cache mémoire + back-pressure                │
│  Ordonnancement séquentiel des steps          │
└───────────────────────────┬──────────────────┘
                            │
                            ▼
┌──────────────────────────────────────────────┐
│                DATA PLANE                    │
│                                              │
│  Sources connectors (CSV, MySQL, APIs, …)    │
│        ↓                                     │
│  Transform engines                           │
│   - Pandas (ligne à ligne)                   │
│   - DuckDB (joins, aggs)                     │
│   - JIT / Artefact compilé (option)          │
│        ↓                                     │
│  Destinations connectors (MySQL, DW, files) │
└──────────────────────────────────────────────┘
```

**Lecture rapide :**

- **Control Plane** → décide *quoi faire*

- **Execution Core** → décide *comment et quand*

- **Data Plane** → fait *circuler et transformer les données*

Si tu veux, prochaine variante possible :

- une version **encore plus abstraite (1 slide C-level)**

- ou une version **orientée développeur** avec focus plugins & interfaces.

Voici **l’ordre exact des appels**, du point d’entrée jusqu’aux données, **sans blabla**, étape par étape.

---

## 1. Point d’entrée

1. **Utilisateur**
   
   - Lance :
     
     ```
     smartetl run --config etl-config.yaml
     ```

2. **CLI (`cli/main.py`)**
   
   - Parse les arguments
   
   - Appelle :
     
     ```
     etl.engine.run_job(config_path)
     ```

---

## 2. Control Plane (préparation)

3. **API publique (`etl/engine.py`)**
   
   - Crée un `JobContext`
   
   - Appelle le chargeur de config :
     
     ```
     ConfigLoader.load(config_path)
     ```

4. **Config Loader (`internal/config/loader.py`)**
   
   - Lit les fichiers YAML
   
   - Appelle le résolveur de secrets :
     
     ```
     secrets.resolve_all(config)
     ```

5. **Secrets Resolver (`internal/config/secrets.py`)**
   
   - Résout `${ENV:}`, `${VAULT:}`, etc.
   
   - Retourne une config **complète et exploitable**

6. **Parsers (`internal/parser/*.py`)**
   
   - `SourceParser.parse()`
   
   - `DestinationParser.parse()`
   
   - `TransformParser.parse()`
   
   - Produit un **Plan d’exécution (AST)** ordonné

---

## 3. Initialisation du job

7. **Engine**
   
   - Instancie :
     
     - les **connecteurs** via `connector.registry`
     
     - les **transform engines** via `transform.registry`
   
   - Passe tout à l’Executor

8. **Executor (`internal/runner/executor.py`)**
   
   - Reçoit :
     
     - Plan d’exécution
     
     - Connecteurs source/destination
     
     - Engines de transformation
   
   - Initialise le cache et le back-pressure

---

## 4. Exécution du pipeline (boucle principale)

9. **Executor → Source Connector**
   
   - Appelle :
     
     ```
     source.extract_batches()
     ```
   
   - Les batches sont envoyés vers le cache

10. **Cache (`internal/cache/memory.py`)**
    
    - Stocke les batches
    
    - Si seuil atteint → bloque l’extraction (back-pressure)

11. **Executor → Transform Engine**
    
    - Récupère un batch depuis le cache
    
    - Pour chaque step du plan :
    
    ```
    transform_engine.apply_step(batch, step)
    ```

12. **Transform Engine**
    
    - Route :
    
    - vers **Pandas** pour calculs ligne-à-ligne
    
    - vers **DuckDB** pour joins / aggregations
    
    - Retourne un batch transformé

13. **Executor → Destination Connector**
    
    - Appelle :
    
    ```
    destination.load_batches(batch)
    ```
    
    - Gestion transaction / retry / erreurs

---

## 5. Gestion erreurs & hooks (transversal)

14. **En cas d’événement**
    
    - `executor` appelle :
    
    - `hooks.before_step()`
    
    - `hooks.after_step()`
    
    - `hooks.on_error()` si exception

15. **Error Handler (`internal/runner/error_handler.py`)**
    
    - Applique la policy :
    
    - fail_fast
    
    - skip_row
    
    - retry
    
    - deadletter (plugin)

---

## 6. Logs & métriques

16. **À chaque étape**
    
    - `logger.structured.log(event)`
    
    - `metrics.increment(...)`

17. **Sinks**
    
    - Envoient les métriques/logs vers :
    
    - stdout
    
    - fichiers
    
    - Prometheus / Datadog (plugins)

---

## 7. Fin de job

18. **Executor**
    
    - Ferme connecteurs
    
    - Vide le cache
    
    - Compile les stats finales

19. **Engine**
    
    - Construit `JobResult`
    
    - Le retourne à la CLI

20. **CLI**
    
    - Affiche :
    
    - succès / échec
    
    - stats clés
    
    - durée totale

---

### 🔑 Résumé ultra-court

```
CLI
 → Engine
   → Config + Secrets
   → Parsers → Plan (AST)
   → Executor
     → Source → Cache
     → Transform (Pandas/DuckDB)
     → Destination
     → Hooks / Errors / Logs
```
