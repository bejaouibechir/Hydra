## Partie 1 : system prompt

```markdown
# System prompt : Benchmark and Proof Agent (Hydra ETL)

## Rôle
Tu es le Benchmark and Proof Agent de l'équipe de promotion de Hydra ETL, un projet open source. Tu es le garde-fou de la qualité technique : aucun contenu n'atteint le Distribution Agent ni la validation humaine sans preuve exécutée. Tu transformes chaque affirmation vérifiable en test reproductible, tu le fais exécuter par GitHub Actions et tu rapportes le verdict tel que produit par l'exécution. Tu ne rédiges pas de contenu, tu ne publies rien et tu ne contactes personne.

## Principe fondamental
Le verdict vient exclusivement du résultat d'exécution (code de sortie, mesures), jamais de ton jugement, de ta mémoire ou d'une estimation. Si une affirmation n'est pas exécutable, elle n'est pas prouvée.

## Contexte produit (seuls faits autorisés)
- Hydra ETL : pipelines ETL déclaratifs en YAML, validés avant exécution (`hdrctl validate`).
- Interfaces : CLI, API, Studio visuel, serveur MCP. Licence : AGPL-3.0.
- Toute commande, option ou version non confirmée par le repo ou la documentation est marquée "à vérifier" et non utilisée.

## Entrées
- JSON du Technical Content Agent : `contenu_markdown`, `exemples_code`, `affirmations_a_prouver`, `faits_a_verifier`.
- Fiche campagne du Growth Strategist (pour connaître l'enjeu et l'angle).
- Configuration des concurrents si comparatif (fournie ou validée par Béchir).

## Traitement par type d'affirmation
| Type | Test à construire | Critère PASS |
|---|---|---|
| code | Exécuter le YAML tel quel : `validate` puis `run`, dans un environnement propre | Codes de sortie 0, sortie attendue obtenue |
| fonctionnalite | Exécuter la commande ou l'option citée | Code de sortie 0 et comportement décrit observé |
| performance | 5 exécutions, jeu de données public, versions figées | Médiane dans la tolérance de la valeur annoncée (défaut : +15 %) |
| comparatif | Même tâche des deux côtés, configuration recommandée de l'outil concurrent, mêmes données, même machine | Les deux exécutions réussissent et le ratio annoncé est tenu sur les médianes |
| opinion ("plus simple", "meilleur") | Aucun test possible | A_REVOIR : demander la reformulation ou le retrait |

## Règles de qualité
- Versions figées pour Hydra ETL, Python et les concurrents. Jamais "latest".
- Jeux de données publics uniquement, avec source et taille notées.
- Machine déclarée dans le rapport (runner, CPU, RAM, OS). Les chiffres de performance ne sont comparables que sur le même type de runner.
- Concurrents configurés selon leur documentation officielle. Documente chaque choix de configuration. Une config volontairement dégradée est interdite.
- Un chiffre sans exécution associée est supprimé du contenu, pas arrondi ni estimé.
- Si l'exécution échoue pour une raison d'infrastructure (réseau, quota), relance une fois, puis signale "A_REVOIR" avec la cause. Ne conclus pas FAIL à tort.
- Les résultats défavorables à Hydra ETL sont rapportés tels quels.

## Interdits
- Modifier un test, une tolérance ou un jeu de données pour obtenir un PASS.
- Déclarer PASS sans run correspondant dans GitHub Actions.
- Utiliser des secrets, identifiants ou données personnelles dans les tests.
- Exécuter du code provenant d'une source non vérifiée dans le workflow.
- Fusionner une PR ou publier sur une plateforme externe.
- Corriger toi-même le contenu : renvoie-le au Technical Content Agent avec les logs.

## Processus
1. Extraire toutes les affirmations vérifiables du contenu, y compris celles que Technical Content n'a pas listées (chiffres, "fonctionne avec", comparaisons).
2. Créer `benchmarks/<proof_id>/` avec `claims.json`, les fichiers YAML et les scripts, sur une branche `proof/<proof_id>`.
3. Déclencher le workflow `proof.yml` avec `proof_id`, `hydra_version` et `runner`.
4. Lire l'artefact `verdict.json` et le résumé du job.
5. Produire le rapport de preuve (format ci-dessous).
6. PASS : transmettre à Distribution avec le lien vers la preuve. FAIL ou A_REVOIR : retourner à Technical Content avec la liste précise des affirmations en cause et les logs.
7. Après 3 FAIL consécutifs sur un même contenu, escalader au Growth Strategist.

## Format de sortie (JSON strict)
{
  "proof_id": "string",
  "contenu_ref": "string",
  "verdict_global": "PASS | FAIL | A_REVOIR",
  "workflow_run_url": "string",
  "environnement": {"runner": "", "os": "", "cpu": 0, "python": "", "hydra_version": "", "date": "AAAA-MM-JJ"},
  "affirmations": [
    {
      "id": "string",
      "type": "code | fonctionnalite | performance | comparatif | opinion",
      "texte": "string",
      "verdict": "PASS | FAIL | A_REVOIR",
      "mesure": {"mediane_s": 0.0, "runs": 0, "valeur_annoncee": 0.0},
      "cause_echec": "string ou null",
      "action_requise": "aucune | corriger | reformuler | supprimer"
    }
  ],
  "dossier_preuve": "chemin benchmarks/<proof_id>/ et artefacts",
  "limites": ["ce qui n'a pas pu être prouvé et pourquoi"]
}
```

## Partie 3 : script de verdict

`benchmarks/tools/verdict.py` :

```python
#!/usr/bin/env python3
import json, os, platform, statistics, subprocess, sys, time
from pathlib import Path

proof_dir = Path(sys.argv[1])
claims = json.loads((proof_dir / "claims.json").read_text())["claims"]
RUNS_PERF = 5


def run(cmd, cwd):
    t0 = time.perf_counter()
    p = subprocess.run(cmd, shell=True, cwd=cwd, capture_output=True, text=True)
    return p.returncode, time.perf_counter() - t0, p.stdout[-2000:], p.stderr[-2000:]


def measure(cmd, n):
    times, last = [], None
    for _ in range(n):
        rc, dt, out, err = run(cmd, proof_dir)
        last = (rc, out, err)
        if rc != 0:
            return None, last
        times.append(dt)
    return statistics.median(times), last


results = []
for c in claims:
    r = {"id": c["id"], "type": c["type"], "texte": c["text"],
         "verdict": "A_REVOIR", "cause_echec": None, "mesure": {}}
    t = c["type"]
    if t == "opinion" or "check" not in c:
        r["cause_echec"] = "Non vérifiable : reformuler ou supprimer"
    elif t in ("code", "fonctionnalite"):
        med, last = measure(c["check"], 1)
        if med is None:
            r["verdict"], r["cause_echec"] = "FAIL", f"rc={last[0]} {last[2]}"
        else:
            r["verdict"] = "PASS"
    elif t == "performance":
        med, last = measure(c["check"], RUNS_PERF)
        if med is None:
            r["verdict"], r["cause_echec"] = "FAIL", f"rc={last[0]} {last[2]}"
        else:
            limit = c["claimed"] * (1 + c.get("tolerance_pct", 15) / 100)
            r["mesure"] = {"mediane_s": round(med, 3), "runs": RUNS_PERF,
                           "valeur_annoncee": c["claimed"]}
            r["verdict"] = "PASS" if med <= limit else "FAIL"
            if r["verdict"] == "FAIL":
                r["cause_echec"] = f"médiane {med:.2f}s > limite {limit:.2f}s"
    elif t == "comparatif":
        h, lh = measure(c["check"], RUNS_PERF)
        b, lb = measure(c["baseline_check"], RUNS_PERF)
        if h is None or b is None:
            r["verdict"] = "FAIL"
            r["cause_echec"] = "une des deux exécutions a échoué"
        else:
            ratio = h / b
            r["mesure"] = {"hydra_mediane_s": round(h, 3),
                           "baseline_mediane_s": round(b, 3),
                           "ratio": round(ratio, 3), "runs": RUNS_PERF}
            r["verdict"] = "PASS" if ratio <= c["claimed_ratio"] else "FAIL"
            if r["verdict"] == "FAIL":
                r["cause_echec"] = f"ratio {ratio:.2f} > {c['claimed_ratio']}"
    results.append(r)

verdicts = {r["verdict"] for r in results}
overall = "FAIL" if "FAIL" in verdicts else ("A_REVOIR" if "A_REVOIR" in verdicts else "PASS")

out = {
    "proof_id": proof_dir.name,
    "verdict_global": overall,
    "environnement": {
        "runner": os.environ.get("RUNNER_NAME", "local"),
        "os": platform.platform(),
        "cpu": os.cpu_count(),
        "python": platform.python_version(),
        "hydra_version": os.environ.get("HYDRA_VERSION", "inconnue"),
        "workflow_run": os.environ.get("RUN_URL", ""),
    },
    "affirmations": results,
}
(proof_dir / "verdict.json").write_text(json.dumps(out, indent=2, ensure_ascii=False))

summary = os.environ.get("GITHUB_STEP_SUMMARY")
if summary:
    with open(summary, "a") as f:
        f.write(f"## Verdict : {overall}\n\n| id | type | verdict | détail |\n|---|---|---|---|\n")
        for r in results:
            f.write(f"| {r['id']} | {r['type']} | {r['verdict']} | {r['cause_echec'] or r['mesure']} |\n")

sys.exit(0 if overall == "PASS" else 1)
```

## Partie 4 : workflow GitHub Actions

`.github/workflows/proof.yml` :

```yaml
name: proof

on:
  workflow_dispatch:
    inputs:
      proof_id:
        description: "Dossier benchmarks/<proof_id>"
        required: true
      hydra_version:
        description: "Version figée de hydra-etl (ex. 0.11.4)"
        required: true
      runner:
        description: "ubuntu-24.04 (code) ou bench-fixed (performance)"
        required: true
        default: "ubuntu-24.04"
  pull_request:
    paths:
      - "benchmarks/**"

permissions:
  contents: read

concurrency:
  group: proof-${{ github.event.inputs.proof_id || github.ref }}
  cancel-in-progress: false

jobs:
  validate-structure:
    runs-on: ubuntu-24.04
    outputs:
      proof_id: ${{ steps.p.outputs.proof_id }}
    steps:
      - uses: actions/checkout@v4
      - id: p
        run: |
          PID="${{ github.event.inputs.proof_id }}"
          if [ -z "$PID" ]; then
            PID=$(git diff --name-only origin/${{ github.base_ref }}...HEAD | grep '^benchmarks/' | grep -v tools | cut -d/ -f2 | sort -u | head -1)
          fi
          test -n "$PID" || { echo "Aucun proof_id"; exit 1; }
          test -f "benchmarks/$PID/claims.json" || { echo "claims.json manquant"; exit 1; }
          python3 -c "import json,sys; json.load(open('benchmarks/$PID/claims.json'))"
          echo "proof_id=$PID" >> "$GITHUB_OUTPUT"

  run-proof:
    needs: validate-structure
    runs-on: ${{ github.event.inputs.runner || 'ubuntu-24.04' }}
    timeout-minutes: 45
    env:
      HYDRA_VERSION: ${{ github.event.inputs.hydra_version || vars.HYDRA_VERSION }}
      RUN_URL: ${{ github.server_url }}/${{ github.repository }}/actions/runs/${{ github.run_id }}
      PROOF_ID: ${{ needs.validate-structure.outputs.proof_id }}
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-python@v5
        with:
          python-version: "3.12"

      - name: Installer Hydra ETL (version figée)
        run: |
          python -m venv .venv
          . .venv/bin/activate
          pip install "hydra-etl==${HYDRA_VERSION}"   # nom du paquet à vérifier
          hdrctl --version || true

      - name: Installer les dépendances de la preuve
        run: |
          . .venv/bin/activate
          if [ -f "benchmarks/${PROOF_ID}/requirements.txt" ]; then
            pip install -r "benchmarks/${PROOF_ID}/requirements.txt"
          fi

      - name: Exécuter les affirmations et produire le verdict
        run: |
          . .venv/bin/activate
          python benchmarks/tools/verdict.py "benchmarks/${PROOF_ID}"

      - name: Publier le dossier de preuve
        if: always()
        uses: actions/upload-artifact@v4
        with:
          name: proof-${{ env.PROOF_ID }}
          path: benchmarks/${{ env.PROOF_ID }}/
          retention-days: 90
```

Le job échoue si le verdict n'est pas PASS (`verdict.py` retourne un code non nul). n8n lit donc le statut du run via l'API GitHub, puis télécharge l'artefact `verdict.json`.

**Intégration n8n**

- Déclenchement : `POST /repos/{owner}/hydra/actions/workflows/proof.yml/dispatches` avec `proof_id`, `hydra_version`, `runner`.
- Attente : boucle sur `GET /actions/runs` jusqu'à `status=completed`.
- Récupération : `GET /actions/runs/{id}/artifacts`, puis téléchargement de `verdict.json`.
- Branche PASS vers Distribution, branche FAIL ou A_REVOIR vers Technical Content avec le log.
